      Architecture references
      
        
      Platform documentation
      
        
      Use the capabilities Fabric and Foundry provide. Configure and connect them for fraud analytics rather than build separate governance, evaluation or monitoring systems.
      
      
      
      
      
        
      Platform capability is not deployment evidence.
      
        
      Fabric and Foundry are target platforms, not deployed migrations. The existing cloud PoC uses synthetic Azure SQL Database data, an Azure OpenAI query planner and Azure AI Search. The local preview uses fixtures, not cloud connections.
      
        
      These architecture references are not policy citations or answer evidence. They do not establish real-source connectivity, Canadian residency or immutable/WORM retention. Inspect Service details for the current connection; these notes are not a live resource inventory.
      
      
      
      
      Official Microsoft Learn references, reviewed October 20, 2026. Each document opens in a new tab without sending this page's referrer. Online documentation requires internet access and can change; this reference view does not call the analytics or policy APIs.
      
      
      
        
      
          
      01 / Data platform
      
          
      Data ingestion and analytics
      
          
      
            
      Platform provides
      Fabric pipelines and connectors, Warehouse SQL processing and OneLake analytical storage.
      
            
      Configure or integrate
      Connect the actual SQL MI or Oracle source; define fraud tables, metric definitions, approved extracts and freshness. Keep runtime access restricted to approved read-only operations.
      
          
      
          
        
            
      • Azure SQL Database connector overview
        Example of supported ingestion activities, authentication and gateway options; not proof of a SQL MI or Oracle integration.
        • 
            
      • What is Fabric Data Warehouse?
        T-SQL warehousing, ingestion and analytics capabilities.
        • 
            
      • OneLake, the unified data lake
        Shared analytical storage, open formats and shortcuts.
        • 
          
      
          
      A Warehouse can support writes; selecting it does not enforce read-only access. A shortcut can reference data without migrating or copying it.
      
        
      
        
      
          
      02 / Governance
      
          
      Data security and governance
      
          
      
            
      Platform provides
      Fabric access controls, lineage, classification and auditing, with Microsoft Purview integration and information protection.
      
            
      Configure or integrate
      Assign ownership, user and workload access, classifications, sensitivity labels and policies. Confirm licensing and which assets, exports and network configurations are supported.
      
          
      
          
        
            
      • Governance and compliance in Microsoft Fabric
        Built-in governance capabilities and the integration boundary with Purview.
        • 
            
      • Information protection in Fabric
        Sensitivity labels, inheritance, protection and licensing prerequisites.
        • 
            
      • Connect a Fabric tenant to Microsoft Purview
        Registration, authentication and metadata/lineage scanning setup.
        • 
          
      
          
      Some capabilities require additional licensing or are in preview. The linked Purview scanning integration does not support Fabric tenant/workspace private links; resolve this compatibility constraint in the design.
      
        
      
        
      
          
      03 / AI execution
      
          
      Models and AI execution
      
          
      
            
      Platform provides
      Foundry model deployments, processing-boundary choices and tooling for AI applications.
      
            
      Configure or integrate
      Select an available model/version and deployment type. Define fraud-specific prompts and permitted tools, then connect broker-calculated numbers and approved knowledge to the explanation flow.
      
          
      
          
        
            
      • Understanding deployment types in Microsoft Foundry Models
        Processing boundaries and consumption/provisioned deployment choices.
        • 
            
      • Region availability for Foundry Models sold by Azure
        Model/version and deployment-category availability by region.
        • 
            
      • What is Toolbox in Microsoft Foundry?
        Reusable tools, authentication and version management for supported application patterns.
        • 
          
      
          
      The existing PoC model plans typed queries; it is not a new grounded-synthesis implementation. Global and Data Zone deployments do not establish Canada-only processing. Confirm the exact model/deployment processing geography, not just where it can be created; tool features can be in preview.
      
        
      
        
      
          
      04 / Knowledge
      
          
      Knowledge grounding
      
          
      
            
      Platform provides
      Foundry and Azure AI Search retrieval, grounding and citation building blocks.
      
            
      Configure or integrate
      Supply approved policies, SOPs, data dictionaries and rule history. Maintain document permissions and updates, and apply business-specific effective dates, scoped supersession and conflict handling.
      
          
      
          
        
            
      • Connect an Azure AI Search index to Foundry agents
        Indexed grounding, retrieval settings and source citations.
        • 
            
      • RAG and generative AI in Azure AI Search
        Content preparation, classic retrieval and agentic retrieval approaches.
        • 
            
      • Document-level access control in Azure AI Search
        Security filters and supported token-based permission enforcement.
        • 
          
      
          
      Service authentication alone is not document authorization. Native permission features and agentic planning have preview limitations. The linked private Search tool setup requires managed identity and standard VNet injection. Retrieval alone does not decide which conflicting policy governs.
      
        
      
        
      
          
      05 / Quality and operations
      
          
      Evaluation and observability
      
          
      
            
      Platform provides
      Foundry evaluation, monitoring, OpenTelemetry tracing and Application Insights integration.
      
            
      Configure or integrate
      Supply representative fraud questions, independently calculated expected results and quality thresholds. Configure instrumentation, alerts, access, retention and telemetry destinations.
      
          
      
          
        
            
      • Observability in generative AI
        The platform evaluation, monitoring and tracing capabilities behind the architecture.
        • 
            
      • Introduction to cloud evaluation with Microsoft Foundry SDK
        Dataset and response evaluation workflows with project/model prerequisites.
        • 
            
      • Set up tracing for AI agents in Microsoft Foundry
        Connect Application Insights and inspect instrumented executions.
        • 
          
      
          
      Evaluations can incur model consumption charges; feature, region and network restrictions apply. Judge-model scores do not prove exact numerical correctness. Tracing and retention are not immutable/WORM evidence guarantees.
      
        
      
        
      
          
      06 / Deployment boundaries
      
          
      Identity, private networking and residency
      
          
      
            
      Platform provides
      Entra identity, supported private connectivity controls and region-associated capacity/deployment options.
      
            
      Configure or integrate
      Validate a supported Canadian configuration, user access, dependency endpoints and outbound paths. Resolve the existing US diagnostic route before claiming a Canada-only solution.
      
          
      
          
        
            
      • Security in Microsoft Fabric
        Authentication, permissions and workload-specific connectivity controls.
        • 
            
      • Multi-Geo support for Fabric
        Capacity-region placement and documented metadata/transit exceptions.
        • 
            
      • Configure network isolation for Microsoft Foundry
        Inbound private endpoints, DNS and outbound network isolation setup.
        • 
          
      
          
      Private access is not a blanket residency guarantee. Fabric metadata/transit exceptions, model processing geography, telemetry and tool dependencies must all be assessed. Private inbound endpoints do not automatically secure every outbound connection.
      
        
      
      
      
      
      
        
      What remains solution-specific
      
        
      Fraud data modelling and metric definitions, controlled data access, business prompts, policy applicability, grounded explanations and answer-level evidence. Use native platform services for the surrounding capabilities.
      
        
      Two requirements still need explicit proof: correct numerical answers against independently calculated expectations, and acceptable performance over the approximately 1 TB source under a representative workload. Platform documentation and small synthetic-fixture results do not establish either production requirement.
